# 1. OpenCV를 이용하여 개발된 제품 및 기능
OpenCV(Open Source Computer Vision Library)는 학술 연구뿐만 아니라 실제 상용 제품에도 광범위하게 사용됩니다. 대표적인 사례와 핵심 기술은 다음과 같습니다.

* ### 모바일 문서 스캐너 앱 (예: CamScanner, Adobe Scan)
    * **기능:** 스마트폰으로 찍은 삐뚤어진 문서 사진을 평평하고 깔끔하게 스캔된 문서처럼 변환합니다.
    * **핵심 기술:** 캐니 에지 검출(Canny Edge Detection)과 허프 변환(Hough Transform)을 사용하여 문서의 외곽선(직선)을 찾습니다. 이후 코너점을 추출하고 **투시 변환(Perspective Transform)** 행렬을 계산하여 기하학적 변환을 수행함으로써 이미지를 평탄화합니다.
* ### 자율주행 및 ADAS (첨단 운전자 보조 시스템)
    * **기능:** 차량 카메라 센서를 통해 차선을 인식하고 전방의 보행자나 차량을 탐지합니다.
    * **핵심 기술:** OpenCV의 **DNN(Deep Neural Network) 모듈**을 활용하여 YOLO, SSD와 같은 객체 검출(Object Detection) 딥러닝 모델을 실시간 추론(Inference)하는 데 주로 사용합니다.
* ### 스마트폰 카메라 앱의 얼굴 인식 및 필터**
    * **기능:** 카메라 뷰파인더에서 사용자의 얼굴을 찾아 초점을 맞추거나 AR 스티커를 합성합니다.
    * **핵심 기술:** 하아 캐스케이드(Haar Cascade) 방식이나 랜드마크 검출(Landmark Detection) 알고리즘을 이용해 얼굴의 바운딩 박스(Bounding Box)와 주요 특징점을 빠르고 정확하게 찾아냅니다.

# 2. 라이브러리(Library)의 의미
소프트웨어 공학에서 **라이브러리**란, 자주 사용되는 특정 기능(함수, 클래스 등)들을 미리 컴파일(Compile)하여 모아둔 코드의 집합체입니다.

* **의미와 가치:** 영상을 흑백으로 변환하거나(RGB to Grayscale), 가우시안 필터(Gaussian Filter)를 적용하기 위해 복잡한 컨볼루션(Convolution) 연산과 행렬 수식을 매번 밑바닥부터 작성할 필요가 없습니다. 누군가 고도로 최적화해 둔 `cv::cvtColor`나 `cv::GaussianBlur` 같은 함수들을 가져다 쓰기만 하면 됩니다. 즉, 재사용성(Reusability)을 높여 '바퀴를 다시 발명하지 않도록' 도와주는 도구 모음입니다.

# 3. 오픈소스(Open Source)의 의미
**오픈소스**는 소프트웨어의 설계도에 해당하는 소스 코드(Source Code)가 대중에게 공개되어 있어, 누구나 합법적으로 접근하여 열람, 수정, 재배포할 수 있는 소프트웨어를 뜻합니다.

* **OpenCV의 예시:** OpenCV는 현재 **Apache 2.0 라이선스**를 따르고 있습니다. 이는 학술적 목적은 물론 상업적 목적으로도 무료로 사용할 수 있음을 의미합니다. 소스 코드가 공개되어 있으므로, 특정 함수의 내부 연산이 C++ 및 어셈블리 레벨에서 어떻게 최적화되어 있는지 직접 분석하고 수정할 수 있습니다.

# 4. Windows 운영체제 환경변수 중 Path 변수의 기능
<img width="1871" height="957" alt="image" src="https://github.com/user-attachments/assets/f97a2365-88d0-4511-8e6c-e03d89ebb5dd" />

운영체제에서 **Path 변수**는 명령 프롬프트나 실행 파일이 특정 파일(주로 실행 파일 `.exe` 또는 동적 링크 라이브러리 `.dll`)을 찾을 때 **우선적으로 탐색해야 할 디렉터리(폴더)들의 경로 목록**을 지정하는 환경변수입니다.

* **OpenCV에서의 중요성:** 프로그램이 실행될 때 `opencv_world4xx.dll` 파일이 필요합니다. 만약 Path 환경변수에 OpenCV의 `bin` 폴더(DLL이 있는 곳) 경로를 등록해두지 않으면, 운영체제는 해당 DLL을 찾지 못해 "DLL을 찾을 수 없습니다"라는 런타임 에러(Runtime Error)를 발생시키고 프로그램을 강제 종료합니다.

# 5. 프로그램 개발과정인 편집, 컴파일, 링크, 실행 단계와 라이브러리의 역할
C++ 기반의 프로그램은 크게 4단계를 거치며, 실제 빌드 과정에서는 컴파일 직전에 **전처리(Preprocessing)** 과정이 필수적으로 개입합니다.

1. **편집 (Edit):** 프로그래머가 C++ 문법에 맞춰 소스 코드(`.cpp`)와 헤더 파일(`.h`, `.hpp`)을 작성하는 단계입니다.
    * **(1.5) 전처리 (Preprocess):** 본격적인 컴파일 직전에 전처리기(Preprocessor)가 동작하여 `#include <opencv2/opencv.hpp>`와 같은 헤더 파일을 소스 코드에 포함(텍스트 복사)시키고, 매크로(`#define`)를 치환하며, 주석을 제거하는 사전 작업을 수행합니다.
2. **컴파일 (Compile):** 전처리가 완료된 텍스트 형태의 소스 코드를 기계어(0과 1)로 번역하여 **오브젝트 파일(Object File, `.obj`)** 로 변환하는 단계입니다. 이때 엄격한 C++ 문법 오류(Syntax Error)를 검사합니다.
3. **링크 (Link):** 컴파일된 여러 개의 오브젝트 파일들과 **라이브러리(`.lib`)** 를 하나로 묶어 최종 실행 가능한 파일(`.exe`)을 생성하는 단계입니다.
4. **실행 (Execute):** 생성된 `.exe` 파일을 메모리(RAM)에 적재하여 CPU가 명령어를 수행하는 단계입니다.

* **링크 단계에서 라이브러리의 역할:** 컴파일(및 전처리) 단계에서는 `cv::imread()`라는 함수가 존재한다는 '선언(Declaration)'만 확인합니다. **링커(Linker)** 는 우리의 오브젝트 파일이 호출한 함수의 주소를 라이브러리 파일에 있는 '실제 구현부'와 찾아 서로 **연결(Resolution of undefined references)** 해주는 핵심적인 역할을 합니다.

# 6. 정적 라이브러리(SLL)와 동적 라이브러리(DLL)의 차이 및 링크 시점
라이브러리는 프로그램에 연결(Link)되는 **'시점'과 '방식'**에 따라 두 가지로 나뉩니다.

<img width="1742" height="984" alt="image" src="https://github.com/user-attachments/assets/c1d8e4d4-b2f0-4824-9201-0e9d55243e04" />

* **정적 라이브러리 (SLL: Static Link Library, `.lib` 또는 `.a`)**
    * **링크 시점:** **컴파일-링크 타임 (Compile & Link-time)**
    * **설명:** 링커가 실행 파일(`.exe`)을 만들 때, 라이브러리 파일 안에 있는 실제 기계어 코드를 통째로 복사하여 `.exe` 파일 안에 집어넣습니다.
    * **특징:** 실행 파일 하나만 있으면 단독으로 실행 가능하지만, 코드가 중복 포함되므로 실행 파일 용량이 커지고 메모리 효율이 떨어집니다.

* **동적 라이브러리 (DLL: Dynamic Link Library, `.dll` 또는 `.so`)**
    * **링크 시점:** **런타임 (Run-time, 프로그램 실행 시점)**
    * **설명:** 링크 단계에서는 코드를 복사하지 않고, "실행할 때 어떤 DLL 파일의 어느 위치에 있는 함수를 가져다 쓰겠다"는 **참조 정보(Reference)** 만 실행 파일에 기록합니다.
    * **특징:** 프로그램이 메모리에 적재되어 실행될 때 실제 코드가 동적으로 연결됩니다. 여러 프로그램이 하나의 DLL을 공유할 수 있어 메모리와 디스크 공간을 크게 절약합니다. OpenCV 환경 설정 시 주로 이 방식을 사용합니다.
