# 실습과제1
### 얕은 복사 (Shallow Copy)
`cv::Mat` 객체의 대입 연산자(`=`)나 복사 생성자를 사용할 때 발생합니다. 영상의 픽셀 데이터(메모리 버퍼) 자체를 복사하는 것이 아니라, 행렬의 크기(rows, cols) 및 타입 등을 담은 **헤더(Header) 정보**와 실제 데이터가 위치한 메모리 주소(Pointer)만 복사합니다. 내부적으로는 메모리 해제를 관리하기 위해 참조 횟수(Reference Count)만 1 증가시킵니다.

* **장점:**
    * **극대화된 연산 효율성:** 화소 데이터 전체를 복사하는 과정이 생략되므로 O(1)의 시간 복잡도로 연산이 즉시 완료됩니다.
    * **메모리 절약:** 수십 메가바이트에 달하는 고해상도 이미지 데이터를 함수 인자로 전달하거나 반환할 때, 추가적인 메모리 할당(Allocation) 오버헤드가 발생하지 않습니다.
* **단점:**
    * **데이터 종속성에 따른 훼손 위험:** 원본 객체와 복사본 객체가 동일한 데이터 메모리 버퍼를 공유합니다. 따라서 복사본에서 특정 화소(Pixel) 값에 접근하여 마스크 연산이나 화소 처리를 수행하면, 원본 영상의 데이터도 동일하게 변형되는 의도치 않은 부작용(Side-effect)이 발생합니다.

---

### 깊은 복사 (Deep Copy)
`cv::Mat::clone()` 또는 `cv::Mat::copyTo()` 멤버 함수를 명시적으로 호출할 때 발생합니다. 원본 영상과 동일한 크기 및 채널을 가진 **새로운 메모리 공간을 동적 할당**한 후, 모든 픽셀 데이터(행렬의 원소)를 새 공간으로 일일이 복사합니다.

* **장점:**
    * **완벽한 데이터 독립성 보장:** 원본과 복사본이 완전히 분리된 별개의 메모리 주소를 갖습니다. 복사본에 가우시안 필터(Gaussian Filter)를 적용해 블러링(Blurring)을 수행하거나, 에지 검출(Edge Detection)을 하더라도 **원본 데이터는 초기 상태 그대로 안전하게 보존**됩니다.
* **단점:**
    * **성능 저하 및 메모리 소모:** 영상의 전체 픽셀 수(Width × Height × Channels)에 비례하는 O(N)의 시간 복잡도와 추가 메모리가 요구됩니다. 실시간 영상 처리(Real-time Video Processing) 환경의 루프 내부에서 불필요하게 깊은 복사를 남발할 경우, 심각한 성능 병목(Bottle-neck) 현상의 원인이 됩니다.
